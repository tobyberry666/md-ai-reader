# DSH MD Reader Implementation Plan

> **For agentic workers:** Execute inline using executing-plans, then use requesting-code-review for an independent review. Track the steps below.

**Goal:** Ship an installable DSH plugin with a Markdown reader and independent native AI conversation per document.

**Architecture:** Register a dedicated main panel using DSH slots/layout. Bind the native conversation and composer to document-owned sessions. Keep document persistence, selection capture and context preparation independent of presentation.

**Tech Stack:** JavaScript ESM, DSH's React and slot runtime, Node built-in test runner, installed browser tooling for interaction checks.

## Global Constraints

- Target installed DSH Desktop 0.2.1-rc.2 and dsh-claude-style 0.16.2.
- Reuse native sessions, model configuration, permissions and tools.
- Never silently truncate a document or replace full context with a summary.
- Reading and selecting never call a model.
- Isolate all work in the new dsh-md-reader directory and its own codex/md-reader branch.
- No changes to existing side-chat or composer plugins.

### Task 2: Documents and full context

Files: `src/documents.js`, `src/context.js`, `test/documents.test.mjs`, `test/context.test.mjs`.

- [ ] Write failing tests for file validation, document identity, persistence, independent session mappings and context boundaries. The full-context test uses a terminal sentinel:

```js
const text = '# Example\n' + 'body\n'.repeat(10000) + 'END_SENTINEL_7391';
assert.ok(makeDocumentContext({ name: 'example.md', text }).includes('END_SENTINEL_7391'));
```

- [ ] Run `node --test test/documents.test.mjs test/context.test.mjs`; confirm the missing behavior fails.
- [ ] Implement document state and native full-context binding. Await successful injection before allowing send; preserve input and show errors on failure.
- [ ] Rerun those tests; confirm all pass, including no automatic model request on import.

### Task 3: Native page and selection bridge

- [ ] Write integration expectations before implementation: the panel registers, native conversation receives the document session ID, selection excludes UI chrome, switching documents preserves independent state, and dispose removes listeners and slots.

- [ ] Implement a minimal two-pane page: import/drop target, tabs, collapsible TOC, search, reader, adjustable divider, context status, quote bridge and the native conversation/composer.
- [ ] Bundle using local build tooling and DSH runtime dependencies. Do not ship extracted DSH sources or credentials.
- [ ] Run browser checks at desktop and narrow sizes, light/dark themes, quote capture, drag/drop, search and document switching. Inspect screenshots and adjust only defects affecting this design.
